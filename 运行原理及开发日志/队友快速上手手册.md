## 4. 标准闭环（每次改需求的固定流程）

**改代码 → 构建 → 部署 → 验证 → Git → 日志**，一步不能少。

### Step 1 改代码
- 前端：改 `web/src/**`；**新文案必须同步 zh.js + en.js**
- 后端：改 `server/src/**`；**改了模型表结构 → 记住要跑迁移 SQL（Step 3）**

### Step 2 构建（本机）
```powershell
cd E:\python_learning\campus-trade\web
npm run build
# 记住产物 hash，例如 dist/assets/index-xxxx.js —— 用它判断服务器是否真上线
```

### Step 3 部署（服务器，SSH）
**前端**（打包 → 上传 → strip 解压覆盖）：
```bash
# 本机：
tar -czf dist.tar.gz -C web dist
# sftp 传到服务器 /tmp/dist.tar.gz，然后：
cd /www/wwwroot/121.40.219.139
rm -rf assets icons index.html manifest.json sw.js
tar -xzf /tmp/dist.tar.gz --strip-components=1   # ⚠️ 必须 --strip-components=1！
grep -oE 'assets/index-[^"]+[.]js' index.html    # 确认新 hash 已上线
```

**后端**（⚠️ 解压到 pm2 实际目录）：
```bash
# 本机：
tar -czf server.tar.gz --exclude=node_modules --exclude=uploads -C server .
# sftp 传到服务器 /tmp/server.tar.gz，然后：
cd /www/wwwroot/campus-trade-server
tar -xzf /tmp/server.tar.gz --overwrite
pm2 restart campus-api
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3000/api/health   # 期望 200
```

**数据库迁移**（只有改了模型表结构才需要）：
```bash
mysql -u campus_user -pwrn123 campus_trade -e "ALTER TABLE 表名 ADD COLUMN ... "
pm2 restart campus-api
```

### Step 4 验证（交付前必须做）
- **API 验证**：用 urllib/requests 打 `http://121.40.219.139:3000`（登录取 token 再测业务接口），关键用例跑一遍
- **浏览器验证**：Edge 打开 `http://121.40.219.139`，**Ctrl+Shift+R 硬刷新**（缓存坑，见第 5 节）
- **上线判定**：`curl http://121.40.219.139/ | grep index hash` 必须等于本机 build 输出的 hash，浏览器刷新才有意义
- 测试产生的脏数据（如"测试书"）要清理掉

### Step 5 Git（本机）
```powershell
cd E:\python_learning\campus-trade
git add -A
git commit -m "feat: 具体功能描述"    # feat: 功能 / fix: 修复 / docs: 日志
git push origin main
```
⚠️ `.env`、`node_modules`、`web/dist`、`uploads` 不应进 Git（确认 .gitignore 已覆盖）。

### Step 6 日志（与代码同一次提交）
- `开发日志.md` 末尾追加新节：`### N. 标题（日期）`，内容：需求 → 后端改动 → 前端改动 → 数据库迁移 → 验证结果 → Git 提交
- 顶部"Git 提交记录表"加一行：`| commit | 说明 |`
- commit 后 `git push`（日志与代码分两个 commit：feat 一个、docs 一个）

## 5. 血泪坑（必看，全是实战踩出来的）

1. **前端"没更新"** → 90% 是没 `--strip-components=1`，解出了 `dist/` 子目录，旧 index.html 残留。判定一律以服务端 grep 的 hash 为准，**不要信浏览器**。
2. **后端"白部署"** → 解压错目录（解到 `/www/wwwroot/campus-api` 而非 pm2 真实 cwd `/www/wwwroot/campus-trade-server`），进程没跑新代码。改完必 `pm2 restart campus-api`。
3. **图片上传 400/HEIC** → 大图必须先经 sharp 预处理（旋转 + 最长边1280 + JPEG q82）；上传上限 `MAX_FILE_SIZE=15728640`（15MB）；接受所有 `image/*`。
4. **拍照识别失败** → 分三步：`front`（封面→书名，无书名 422）、`back`（封底条形码→ISBN，无 ISBN 422）、合并核对弹窗；识别结果返回 `cover` 和 `marketMatches`（同书在售/求购数）。
5. **AI 助手"不聪明"** → 系统提示词别写太死（只答平台问题就废了）；允许闲聊/知识问答；返回 JSON 要兼容被 markdown 代码块包裹（解析前去 ``` 包裹）。
6. **i18n 缺 key** → 英文界面白屏/显示 key 名，就是新文案只加了 zh.js。规则：**动文案 = 动两个文件**。
7. **多轮记忆丢失** → AI 对话状态由前端按会话维护并传 context（切换页面后丢失是前端未恢复历史，改动时先确认会话 id/历史加载逻辑）。
8. **表结构改动** → 只改 models 不跑迁移 SQL 必报"Unknown column"。迁移要幂等（重复执行不报错）。
9. **测试数据污染** → 验证完删掉测试产生的记录（如 `DELETE FROM wishlists WHERE title='测试...'`）。
10. **Nginx 反代** → `/uploads` 与 API 80 端口是 Express 直接响应，不需要额外 Nginx 反代配置（改多了反而出问题）。
